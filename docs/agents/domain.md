# Domain docs

Before exploring a domain area, read the root `GLOSSARY.md` and the relevant
architecture decision records in `docs/adr/`. If either is absent, continue
with the task. The domain-modeling skill creates these documents as terms
and decisions are settled.

Use glossary terms in tickets, proposals, code, and tests. Flag missing terms
for domain modeling. If a proposal conflicts with a recorded decision, cite
the ADR and explain why the decision merits review.
